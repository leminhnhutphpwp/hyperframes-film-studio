# Making a paper cut-out history film

The whole path from idea to upload. Run every command from the studio root.
Each film belongs to a channel: `projects/<channel>/<film>`. The channel's identity and its own rules live in
`channels/<channel>/README.md` — read it before you start writing.
A sample chapter is included: `templates/film/examples/` ("The Ides of March", built from the starter assets in `library/`).

```
sources → narration → voice → artwork → scenes → checks → render → film check
        → thumbnail → title/description → upload (private) → make public once approved
```

## Project layout

```
projects/<channel>/<film>/
  source/            original script, facts.md (date checks, a second source besides Wikipedia)
  narration.vi.txt   source-language narration: "NNN sentences", blank line = paragraph break, "# ── Chapter N · Name" = chapter
  audio/vi-story/    pNN.wav, lines.json, timing.json, loi-ke-toan-bo.m4a (the full assembled narration)
  audio/sfx/         self-made sounds (muskets, cannon, music bed)
  chNN/              chapter.json + js/scenes.js (the chapter's scenes); index.html and js/data.js are generated by chapter_build
  shared/            engine.js, stage.js, overlay.js, map.js, template.html, chapter_build.py, map/spec.json
  battles/<battle>/  battle.json → battles/render.sh → clips/<battle>.webm
  render_all.sh      builds + renders every chapter, joins them, mixes the music bed → out/<film>.mp4
  publish/           youtube-meta.json, thumb/ (art.png, art.txt, thumb.json), thumbnail.jpg, youtube.json (upload record)
  archived.json      videos/builds moved to the archive drive (written by tools/archive_videos.py)
```

New project: `mkdir -p projects/<channel>/<film>`, then copy `templates/film/shared` (the latest engine plus the
cinematic layer `fx.js`; see `templates/film/README.md`).
**Do not rebuild** a film that is already published just to add new effects. Improvements apply from the next film on.

## 0. Every film must differ from the last one (read before you start)

YouTube does not ban synthetic voices or AI images, but it does not monetise channels whose videos look mass-produced
(the "inauthentic content" policy, July 2025). The usual mistake: several episodes that are almost the same film —
same backdrop, small puppets standing in a row in wide shots, no close-ups, one colour for the whole film. So for each film:

1. **Before writing** — put in `source/facts.md`: a one-sentence thesis for the film (a point of view, not an
   encyclopedia summary), two little-known details or points historians disagree on, and a second source besides Wikipedia.
2. **Before building** — write in the project README: a signature scene only this film has (for example the double
   siege lines of a siege); an opening that differs from the previous film (a strong scene / a question / an object);
   a colour grade per chapter (`fx.grade`); one or two close-up tableaux (`tools/tableau.py`) for each emotional moment;
   at least one night, weather or firelight scene if the story has one; as many chapters as the story needs, not a fixed number.
3. **Backdrops and characters** — paint a new backdrop for the film's main setting. Do not reuse a backdrop that was
   the main setting of the previous film. The camera should not stay in the wide shot: push in to a medium shot on
   whoever is speaking (`fx.focus`).
4. **Before the final render** — put the new film next to the two previous ones:
   `.venv/bin/python -I tools/filmsheet.py /tmp/compare.jpg <new film>.mp4 <previous film>.mp4 <the one before>.mp4`.
   Fix any row that looks like the same film.
5. **After publishing** — pin a comment with a discussion question. After about a week, check the audience retention
   graph in YouTube Studio and note in the project README where viewers drop off, so the next film can learn from it.

## 1. Sources and narration — `narration.vi.txt`

- Write it as **storytelling**, directly in the narration language (do not translate sentence by sentence). The voice
  comes first; the pictures follow the voice.
- Open with 10–15 s of the strongest scene, then the title card. Leave about 15 s at the end for the YouTube end screen.
- Vietnamese narration: in Vietnamese `năm` means both "year" and "five", so the TTS voice can run the two together.
  Open a date with `Vào năm…,` ("In the year…,"). For a year that starts with 5, write `Vào năm… 52` so the voice
  pauses between the two `năm`. Write "5 years" as `nửa chục năm` ("half a decade") instead of `5 năm`.
- Where historians still disagree, say so, but only where it really matters. Figures given by one side (Caesar,
  Plutarch) are reported as theirs.

## 2. Voice

```bash
P=projects/<channel>/<film>; mkdir -p $P/audio/vi-story
runtime/venv-vieneu/bin/python tools/tts_vieneu.py $P/narration.vi.txt $P/audio/vi-story   # default VieNeu voice
.venv/bin/python -I tools/assemble_narration.py $P/narration.vi.txt $P/audio/vi-story $P/audio/vi-story/loi-ke-toan-bo.m4a --pause 3=2.6
```

`runtime/` (venvs + the VieNeu/Kokoro models) is not in git — to reinstall it see `docs/setup.md`. The narration is
read one paragraph at a time so the intonation flows. `--pause N=seconds` adds silence after sentence N for the title
card. To redo some paragraphs: `--only 5,7`, then assemble again.

## 3. Artwork (the `library/` library)

Look things up first and only draw what is missing: `.venv/bin/python -I tools/asset.py list --era ... --text ...`.
Drawing goes through the Codex CLI on your machine or an Images API (chosen with `IMAGE_BACKEND` in `.env`;
`asset.py draw kit|heads|props|cutout|backdrop|terrain ...`). Draw **at most 3 images at once**, and do not draw while
rendering or running TTS (the machine runs out of RAM). Collect a project's draw commands in
`$P/batches/<name>_batch.sh` so they can be re-run (draw batches for the shared library, not tied to a film, go in `tools/batches/`).
Asset ids must be unique (chapter_build stops on a duplicate). Maps: `tools/map_render.py shared/map/spec.json ...`.
Bundled sound library: `library/sfx/CATALOG.md` (wind, rain, markets, animals, short music cues — licences checked).
Self-made sounds, no downloads: `tools/synth_audio.py` (muskets, cannon, sword clashes, lyre/tanpura beds).
Downloaded music: ask first.

## 4. Building scenes

Main characters, close-up characters, animals and riders: **draw the whole figure** for each pose
(`tools/anim_frames.py`, `templates/film/README.md`) — list every pose the script needs first. Jointed cut-out puppets
are only for crowds and distant soldiers.
Before building: run `tools/rigtest.py` for every action the film uses (walk, sit, kneel, ride a horse/elephant,
animals) with the film's own costumes. One image takes a few seconds and shows a bent neck, a broken joint or sunken
feet right away (`templates/film/README.md`).
Each chapter: `chNN/chapter.json` (assets, backdrops, battle clips) + `chNN/js/scenes.js`. Scenes follow the voice
with `cue(n, "word")` — the moment that word is spoken in sentence n. Battles: `templates/battle` →
`battles/<battle>/battle.json` (`fire`, `rout`, `charge`, `volleyLoss`) → `battles/render.sh` → `clips/*.webm`.

```bash
.venv/bin/python -I $P/shared/chapter_build.py $P/ch03          # generates index.html + js/data.js
.venv/bin/python -I tools/framecheck.py $P/ch0*                 # CUT / MAP / BIG
```

The cinematic layer (colour, light, dust, rain, letterbox bars, close-up tableaux, ink/paper transitions):
`templates/film/README.md`.
Preview a few frames: `tools/frames.py <chapter> /tmp/f --times 1,5,9 --scale 0.5`. Common mistakes: the camera is so
far out that the map edge shows, ships on dry land, oversized props, characters cut off at the frame edge.

## 5. Render

```bash
NODE_OPTIONS=--max-old-space-size=8192 $P/render_all.sh          # or: $P/render_all.sh 03 04 (some chapters)
```

4 workers (`WORKERS=`), about 1–3 minutes per chapter. Only one render at a time. Output: `out/<film>.mp4` +
`out/chapters.txt`. Once joined, the chapter renders are moved to the archive drive in step 11.

## 6. Checking the film

```bash
F=$P/out/<film>.mp4
ffmpeg -v info -i $F -vf blackdetect=d=0.5:pix_th=0.06 -an -f null - 2>&1 | grep blackdetect   # only the final fade is allowed
ffmpeg -v error -y -i $F -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t\,30)',scale=384:216,tile=5x4" -frames:v 1 /tmp/sheet.jpg
```

Note: blackdetect only prints with `-v info`. Use the contact sheet to check text, framing and whether the battle
clips are long enough.

## 7. Thumbnail

Draw it separately; **do not** grab a frame from the film. Try a **photorealistic, cinematic image** (`--real`; it
usually pulls more clicks than the paper style) with words that spark curiosity but stay true to the film. Guidelines
(not a fixed template — think up a fresh idea for each video so it stands out): one large subject with a clear
emotion (a close face, a confrontation, a contrast in scale, one object that tells the story), hard light, a dark
background; 2–4 bold words as the hook — do not repeat the title; a small series label (JULIUS CAESAR · PART 1).
Check it at about 200 px.

```bash
.venv/bin/python -I tools/thumb_art.py $P/publish/thumb/art.png --real --side left "Close-up of ... tense stare ..."
python3 tools/thumbnail.py $P/publish/thumb/thumb.json        # → publish/thumbnail.jpg (+ variants if any)
```

`thumb.json`: each entry has `art`, `out`, `lines` (line 1 white, line 2 yellow), `badge`, `side`
(left/right/top/bottom), `font` (sans/serif), `fs`, `pos` (crop box), `c1`/`c2`, `fade`, `margin`. Save the drawing
prompt in `art.txt` so it can be redrawn.

## 8. Title and description — `publish/youtube-meta.json`

`title`, `description` (summary, notes on sources/accuracy, **chapter timestamps** from `out/chapters.txt`, source
list, hashtags), `tags`, `language: "vi"`, `privacyStatus: "private"`, `localizations.en` (English title + description).
**No subtitles** — the narration is already in the channel's language.

## 9. Upload

Only upload once that video has been approved. The same command works for every channel (the channel is taken from
the project folder):

```bash
node publish/youtube/upload.js $P            # preview: file, thumbnail, the token's channel, playlist
node publish/youtube/upload.js $P --yes      # upload as PRIVATE
```

It reads `publish/youtube-meta.json` + `publish/thumbnail.jpg`, finds the video in `out/` or the archive, checks that
the token belongs to the right channel, sets the thumbnail, localisations and playlist, and writes
`publish/youtube.json` and `channels/<channel>/published/<videoId>.json`.
Changing visibility, title or localisations: `publish/README.md`. Making it public, scheduling and the end screen are
done in YouTube Studio.

## 10. English version

The English voice uses Kokoro (`tools/tts_vieneu.py --engine kokoro`), on-screen text comes from `strings.en.json`,
and you build with `LANG_FILM=en`.
A version in another language can go to a sister channel (`languageChannels` in `channel.js`).

## 11. Archiving videos

After publishing, move the videos and builds to the archive drive and keep the film's source:

```bash
.venv/bin/python -I tools/archive_videos.py $P            # preview
.venv/bin/python -I tools/archive_videos.py $P --apply    # move to $STUDIO_ARCHIVE/<channel>/<film>/ (default archive/)
```

This moves everything git ignores in the project (`out/*.mp4`, `chNN/renders/`, the copy of `shared/`, `assets/`,
`shorts/*/build/`, logs); text files in `out/` (chapters.txt…) stay. The list is written to `archived.json`. Nothing is deleted.
